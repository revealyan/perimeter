# АДР 004: supervisor на сервер ставит само приложение по ssh

- Статус: принято (2026-11-13)
- Развилка: поставка без исходников (docs/design/delivery-options.md, вариант A)

## Контекст

Supervisor на сервере работал из исходников (`npx tsx`, полный `npm ci` на 600 МБ), обновлялся руками: архив → scp → подмена папок → `systemctl restart`. Приложение и так держит ssh-подключение к каждому серверу (ssh2 в Electron-main).

## Решение

Как VS Code Remote SSH: supervisor собирается одним файлом (esbuild), приложение по ssh подключения проверяет версию на сервере и по кнопке кладёт сборку в `~/.perimeter/server/<версия>/` пользователя службы. Тяжёлое сервер берёт сам: Node — с nodejs.org со сверкой sha256, Claude Code (платформенный пакет SDK) и node-pty — `npm ci` по lock-файлу из сборки. Переключение — ссылка `current` (прошлая — `previous`), служба `perimeter` запускает `current/start.sh`; не поднялась — сам откат на `previous`. Вход под root → системная служба с `User=`; не под root → служба systemd пользователя.

## Последствия

- Версии клиента и сервера совпадают: версия сборки = `<версия пакета>-<хэш сборки>`, её же supervisor отдаёт в `event:hello`.
- Серверу нужен выход к nodejs.org и registry.npmjs.org; компилятор — только для node-pty (без него терминал идёт запасным путём).
- Ручная выкатка архивом больше не нужна; системные пакеты (Chromium, Xvfb) — пока руками.

## Отвергнуто

- Docker-образ: проекты, git-ключи и терминал оказываются внутри контейнера; на Velohost доступ к Docker рядом с VPN друзей.
- Скрипт `curl | bash` с самообновлением: версии приложения и сервера расходятся.
- Везти всё с компьютера владельца: 340 МБ Claude Code на каждое обновление по каналу ~3 МБ/с.

## Откат

Обратимо: вернуть в юните ExecStart на исходники; папки версий удаляются целиком.
