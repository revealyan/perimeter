# Новый сервер «без лишних движений» (2026-11-23)

Задача владельца: «снял впс-ку, поставил периметр локально — и бам-бам-бам, поехали». Пользователь знает только то,
что дал хостер: **IP и пароль root**. Всё остальное — дело приложения; вопросов по умолчанию ноль.

## Флоу: три экрана

**1. «Подключить сервер»** — IP и пароль (или ключ, если есть) → «Подключить».
Приложение один раз входит паролем, генерирует свой ключ ed25519 (`~/.perimeter-client/keys/<подключение>`),
кладёт публичный в `authorized_keys` и дальше ходит только ключом. Пароль нигде не сохраняется.

**2. Установка — сама, сразу после входа.** Экран — чек-лист шагов (не лог строками), у каждого статус; ошибка —
человеческим текстом и «Повторить шаг»:

- вход по ключу настроен;
- пользователь службы (имя по умолчанию — имя пользователя этого компьютера латиницей, иначе `perimeter`; **без sudo**);
- системные пакеты: git, curl, сборка node-pty (gcc/make/python3), xvfb;
- Node, Claude Code, supervisor, служба `perimeter` (только `127.0.0.1`);
- браузер на сервере: Chrome for Testing + профиль AppArmor, где он нужен;
- docker для агентов: **rootless** под пользователем службы (контейнеры не получают root);
- ключ GitHub пользователя службы сгенерирован.

«Дополнительно» (свёрнуто): имя пользователя, порт, без docker, без браузера.

**3. «Аккаунт и первый проект».**
- Аккаунты: «Взять с этого компьютера» одной кнопкой (если локально они есть) / вход в подписку Claude / ключ API.
- Ключ GitHub: «Скопировать» + «Открыть GitHub» + живая проверка (`ssh -T`) — можно пропустить.
- «Переезд с другого сервера» (если подключения уже есть): перенести аккаунты, MCP, проекты, сессии и журнал
  размышлений с выбранного сервера.
- → «Склонировать проект» / «Новая сессия».

## Права (решение 2026-11-23)

Как на Velohost: системное делает установщик под root, агенты живут под пользователем службы **без sudo**.
Docker — rootless под тем же пользователем (группа `docker` = фактически root — не используем).
Вход не под root: пароль один раз и для `sudo -S`; sudo нет вовсе — служба пользователя (linger),
системные шаги — с подсказкой «попросите root выполнить …».

## Что есть и чего не хватает

| Шаг | Сейчас | Нужно |
|---|---|---|
| Вход | только ключ / ssh-agent | пароль один раз → свой ключ → authorized_keys |
| Пользователь службы | поле руками (под root) | имя по умолчанию, поле — в «Дополнительно» |
| Пакеты | отдельная кнопка «Установить недостающее» | шаг установки |
| supervisor + служба | есть (АДР 004) | шаг чек-листа вместо лога |
| Браузер на сервере | руками (deploy.md) | шаг установки |
| Docker | нет | rootless — шаг установки |
| Ключ GitHub | руками | генерация + копирование + проверка; хранилище ключей сред в настройках подключения |
| Аккаунты | вкладка настроек | шаг 3, перенос с этого компьютера / с сервера |
| Переезд между серверами | нет (руками) | шаг 3 «Переезд с другого сервера» |
