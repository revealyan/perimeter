# Следующий раунд: перенос сессий между средами и телефон (2026-11-10)

Решения владельца: основа дизайна — G + ревью из F (G1/G2) или B + D (BD1/BD2, рисуются); diff — «построчно» и «мутации» (+ «рядом») — сделано в клиенте;
«среды» = **перенос работы** VPS ↔ этот компьютер в обе стороны, при этом можно жить только на VPS или только локально; телефон — фича.

## 1. Перенос сессии между средами

**Что переносится:** история разговора (транскрипт claude `.jsonl`) + настройки сессии (имя, аккаунт, модель, режим, проект — по имени).
**Что само не переносится:** незакоммиченные правки файлов и запущенные процессы — это отдельная развилка ниже.

Механика (протокол уже почти готов к ней):
1. Клиент держит соединения с **обоими** supervisor'ами сразу (иначе перенос — это «переключись, скопируй, переключись», а ждущие сессии другой среды не видны).
2. Источник: `cmd:session.export {sessionId}` → транскрипт + мета; сессия останавливается и уходит в архив с пометкой «переехала → VPS».
3. Клиент передаёт байты в цель: `cmd:session.import {name, project, transcript, profile, model, mode}` → цель кладёт транскрипт в `<CLAUDE_CONFIG_DIR>/projects/<слаг папки проекта здесь>/<id>.jsonl`, переписав поля `cwd` на свою папку, и создаёт сессию в состоянии «остыла» — первое сообщение поднимет её через `--resume` с полной историей.
4. Перенос транскрипта между папками supervisor уже умеет (сделано при смене аккаунта) — переиспользуем.

| Развилка | Варианты | Цена сейчас | Цена потом | Рекомендация |
|---|---|---|---|---|
| **Одно окно на обе среды** | а) два соединения сразу, «Ждут тебя» общий · б) переключатель (как сейчас) | а) ~день: клиент на N соединений | б) перенос неудобен, ждущие другой среды не видны | **а**; среда, которая не настроена, просто не показывается — «только VPS» и «только локально» бесплатно |
| **Правки файлов при переносе** | а) только история + предупреждение · б) «перенести и правки»: `git diff` → патч → `git apply` в цели · в) через git: WIP-коммит в ветку `perimeter/handoff-…`, push, в цели fetch+checkout | а) 0 · б) ~день · в) ~день, нужен общий remote | а) руками пушить · б) конфликты, если цель отстала · в) мусорные ветки | **а сейчас, б следом** (галочка «перенести незакоммиченные правки», с проверкой, что цель на том же коммите) |
| **Старое место после переноса** | а) архив «переехала → …» · б) удалить | 0 | б) теряется след | **а** |

## 2. Телефон: отвечать на разрешения и вопросы откуда угодно

Ограничение: supervisor слушает только `127.0.0.1` на VPS, снаружи — SSH-туннель. Телефону туннель не поднять.

| Вариант | Как | Что умеет | Цена сейчас | Цена потом |
|---|---|---|---|---|
| **А. Телеграм-бот** | модуль supervisor'а: при `permission.request`/вопросе шлёт сообщение с inline-кнопками «Разрешить / Отклонить / Всегда», вопрос — кнопками вариантов; ответ → `respondPermission` | уведомления + ответы, короткий контекст (команда, путь, +N −M) | **1–2 дня**, ничего не открываем наружу (бот сам ходит в Telegram) | диф и лента — только текстом; данные команд проходят через Telegram; allowlist chat id обязателен |
| **Б. Мобильный веб-клиент (PWA) + приватная сеть** | Tailscale/WireGuard до VPS; маленький HTTPS-шлюз на интерфейсе приватной сети → supervisor; PWA — урезанный наш же рендерер; пуши — Web Push | полноценно: лента, диф, ответы, «Ждут тебя» | ~3–5 дней + настройка сети на телефоне | iOS пуши только у установленной PWA; своя авторизация на шлюзе |
| **В. Нативное приложение** | Expo/React Native поверх канала из Б | Live Activities, Face ID на опасные команды, нормальные пуши | 1–2 недели | сторы, подписи, два кода UI |
| **Г. Свой пуш-сервер (ntfy) + ссылка в PWA** | supervisor шлёт пуш в self-hosted ntfy, тап открывает PWA | пуши без Telegram | +1 день к Б | ещё один сервис |

**Рекомендация:** А сразу (максимум пользы за минимум — ответить на разрешение из метро), затем Б как полноценный мобильный клиент на нашем же рендерере; В — только если упрёмся в ограничения PWA (Live Activities, Face ID).

Безопасность в любом варианте: опасные команды (`rm -rf`, `git push --force`, деплой) — подтверждение с телефона только с повторным нажатием/биометрией; журнал «кто и откуда ответил» в supervisor.
