# Что хранит Perimeter и что едет при переезде (2026-11-26)

Владелец: «надо понять, что мы храним и что можем взять с собой — переезд с сервера на сервер вполне реальный сценарий;
и автоматизировать это». Опись — по коду supervisor'а и по живому Velohost.

Классы переносимости:

- **едет** — переносим как есть (пути переписываем под новый сервер);
- **едет-секрет** — переносим, но это ключ/токен: только по туннелю, в логи и в окно не выводим;
- **пересоберётся** — не везём, цель сделает сама (кэш, служебное, бинарники);
- **заново** — не копируем намеренно (приватный ключ сервера, вход, который нельзя делить), цель делает своё;
- **решает человек** — показываем в плане с галкой.

## А. Данные Perimeter на сервере (`~/.perimeter`)

| Что | Файл | Класс | Заметки |
|---|---|---|---|
| Аккаунты: имена, тип, модели, лимиты, флаги | `profiles.json` | едет-секрет | env содержит ключи API / токены подписки; `configDir` переписывается на `accounts/<slug>/.claude` цели |
| Кэш моделей аккаунтов | `profiles-cache.json` | пересоберётся | |
| Проекты: имя, путь, аккаунт/модель по умолчанию; корень хранилища | `projects.json` | едет | пути — от корня хранилища цели (связь по имени, как в синке) |
| Реестр сессий: id, имя, claudeSessionId, cwd, аккаунт, модель, усилие, автокомпакт, проект, архив, воркеры | `state.json` | едет | cwd переписывается; сессии на цели «остывшие», первый ход поднимет с историей |
| Тексты размышлений (по подписи) | `thinking.log` | едет | без него у перенесённых сессий пропадают старые размышления |
| Общие MCP-серверы | `mcp-shared.json` | едет-секрет | заголовки/env с токенами |
| Профиль браузера сервера (входы на сайты) | `rb-profile/` | решает человек | ~50 МБ; входы могут слететь при смене IP |
| Версии supervisor'а | `server/<версия>`, `current`, `previous` | пересоберётся | ставит установщик |

## Б. Claude Code на аккаунт (`CLAUDE_CONFIG_DIR` = `accounts/<slug>/.claude`; у аккаунта по умолчанию — `~/.claude`)

| Что | Класс | Заметки |
|---|---|---|
| Транскрипты сессий `projects/<слаг-пути>/<uuid>.jsonl` | едет | с сессиями; слаг и cwd внутри — под новый путь (`retargetTranscript`) |
| Списки задач `tasks/`, `todos/` | едет | с сессиями (по id сессии Claude Code) |
| Точки отката `file-history/` | решает человек | тяжёлые; без них откат правок старых ходов недоступен |
| Настройки аккаунта `settings.json` | едет | env/модель/разрешения |
| Память пользователя `CLAUDE.md` | едет | |
| MCP аккаунта (`mcpServers` в `.claude.json`) | едет-секрет | остальное в `.claude.json` (онбординг, доверие к папкам) — пересоберётся |
| Свои `skills/`, `commands/`, `agents/` | едет | общие — симлинки на базовую папку; везём содержимое |
| Плагины `plugins/` | пересоберётся | ставятся из маркетплейса по списку |
| Вход подписки `.credentials.json` (OAuth) | заново | refresh-токен вращается: два сервера с одной копией выбьют друг друга. Токен `setup-token` (в env) — едет-секрет |
| `backups/ cache/ session-env/ shell-snapshots/ sessions/ state/ spares/ policy-limits* remote-settings* mcp-needs-auth-cache.json .last-cleanup` | пересоберётся | служебное CLI |

## В. Проекты (корень хранилища, по умолчанию `~/projects`)

| Состояние | Как едет |
|---|---|
| git, всё закоммичено и запушено | клон с remote на цели (нужен доступ: ключ из «С сервера») |
| незапушенные коммиты, локальные ветки (в т. ч. воркеров `perimeter/w-*`), stash | `git bundle` всех локальных refs → клон из бандла, remote — как был |
| незакоммиченные правки | патч (`git diff HEAD --binary`) поверх того же HEAD |
| новые файлы вне git (untracked) и игнорируемые не-тяжёлые (`.env`, локальные конфиги) | архив файлов |
| не git | архив файлов |
| тяжёлое и пересобираемое: `node_modules`, `.venv`/`venv`, `__pycache__`, `dist`, `build`, `.next`, `target`, `.cache`, worktrees `.perimeter/wt/` | не везём — пересоберётся (`npm install` и т. п.) |

## Г. Окружение пользователя службы (вне Perimeter)

| Что | Класс | Заметки |
|---|---|---|
| Приватные SSH-ключи (`~/.ssh/id_*`) | заново | на цели — свой ключ («С сервера» → «Создать» → добавить в GitHub); план показывает, к какому GitHub-логину был ключ источника |
| `~/.ssh/config`, `known_hosts` | решает человек / пересоберётся | known_hosts GitHub пишет «Проверить GitHub» |
| git-имя и почта (`~/.gitconfig`) | едет | |
| вход `gh` (`~/.config/gh`) | заново | токен — войти на цели |
| Системные пакеты (chromium, xvfb, build-essential, docker) | пересоберётся | «Возможности сервера» на цели — план показывает, что было включено на источнике |
| Образы и тома rootless docker (`~/.local/share/docker`) | пересоберётся / решает человек | образы перекачаются; тома с данными — позже, с «Окружением» |
| crontab, пользовательские службы systemd | решает человек | вне Perimeter: показываем, не переносим |
| Прочие файлы в домашней папке | решает человек | показываем крупные, не трогаем |

## Д. Клиент (компьютер владельца, `~/.perimeter-client`, localStorage/IndexedDB)

Ключи приложения к серверам, подключения, настройки окна, кэш лент по среде — не данные сервера. При переезде:
новое подключение (вход паролем → свой ключ приложения), кэш старой среды можно стереть.

## Автоматический переезд (сделано 26.11, v0.2.11)

Владелец: «таб "переезд": либо на готовый сервер бамбамбам — с учётом, что там уже что-то есть, чтобы не сломать
тамошний периметр, — либо скачать архив, а потом загрузить его; галками выбираешь, что перетащить».

**Где:** настройки подключения → «Переезд». Два блока:

1. **Перенести отсюда** — опись этого сервера галками (аккаунты, MCP, проекты, сессии, архив сессий, журнал
   размышлений, профиль браузера, git-имя) + «с ключами и токенами»; «Куда»: другой сервер → «Перенести» или
   «архивом на этот компьютер» → «Скачать архив» (`perimeter-migration-<хост>-<дата>.tgz`; с ключами — хранить как пароль).
   Пункты «сделать на новом» (вход подписки, ключ GitHub, crontab…) — списком без галок.
2. **Загрузить архив сюда** — файл → на сервер кусками → превью → импорт.

**Пакет** — один формат на оба пути (`tar.gz`, `manifest.json` + `accounts/<имя>/` + `mcp-shared.json` +
`projects/<n>/{repo.bundle, patch.diff, files.tgz}` + `sessions/<id>/{session.json, transcript.jsonl, tasks/, todos/}` +
`thinking.log` + `browser.tgz`). git — целиком бандлом (`--all`: ветки, теги, stash), remote остаётся прежним —
цели не нужен доступ к нему; правки — патчем, вне git (`.env` и т. п.) — архивом; тяжёлое (`node_modules`…) не едет.

**Передача** — через приложение кусками по 1 МБ (`cmd:migrate.read` → `cmd:migrate.upload`, строго по порядку),
сверка sha256 перед превью. Серверам доверять друг другу не нужно.

**Импорт не ломает цель** (`cmd:migrate.preview` → галки → `cmd:migrate.import`): аккаунт/MCP/проект/сессия с тем же
именем/id — «уже есть», не трогаем (сессии идут в существующие аккаунт и проект); папка проекта занята чужим — кладём
рядом (`app-2`); файлы аккаунта (settings, CLAUDE.md, skills…) и MCP аккаунта — только недостающие; журнал
размышлений — недостающие записи; свой профиль браузера и git-имя цели не перезаписываются. Повторный импорт того же
пакета ничего не дублирует. Сессии на цели «остывшие» — первый ход поднимает их с историей (resume перенесённого
транскрипта, cwd переписан).

**Проверено:** `scripts/e2e-migrate.ts` — два supervisor'а (разные HOME), настоящий Claude Code: ход на источнике
(«запомни КАШТАН») → пакет → куски → цель со своим аккаунтом и занятой папкой → превью → импорт → ход на цели
видит историю источника; на стенде — то же через окно.

**Дальше:** пароль на архив (шифрование), «Готово — погасить старый», поиск сессий Claude Code вне Perimeter (фоном,
с уведомлением).
