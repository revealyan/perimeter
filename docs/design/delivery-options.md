# Поставка без исходников — варианты (на выбор владельца, ночь 2026-11-12)

> **Решено 2026-11-13** (владелец, всё по рекомендациям): 1 — A, 2 — сервер вместе с supervisor'ом / приложение
> докачивает, 3 — electron-builder NSIS + GitHub Releases. Подвопросы A: оба режима входа (root → системная служба
> с `User=`, не root → служба пользователя), Node и тяжёлое сервер качает сам, обновление — кнопкой. Журнал —
> docs/decisions.md, АДР 004, как пользоваться — docs/deploy.md, раздел 0.

Сейчас всё запускается из исходников: приложение — `vite dev` + `electron .`, локальный supervisor — `node --import tsx
packages/supervisor/src/main.ts` из папки репозитория, на сервере — архив исходников + `npm ci` + `npx tsx` под systemd.
Нужно: приложение ставится установщиком и само обновляется; supervisor на сервер ставится и обновляется без ручной
выкатки. Ниже — развилки по порядку важности, у каждой рекомендация.

## 1. Как supervisor попадает на сервер (блокирует всё остальное)

| Вариант | Как | Цена сейчас | Цена потом |
|---|---|---|---|
| **A. Как VS Code Remote SSH — ставит само приложение** (рекомендую) | «+ Подключение» → приложение по своему же ssh проверяет версию supervisor'а на сервере; нет или старый — кладёт сборку своей версии в `~/.perimeter/server/<версия>/`, переключает службу, держит прошлую для отката (то, что я сейчас делаю руками) | ~2 дня: сборка supervisor'а одним файлом (esbuild) + node-pty + SDK; установщик по ssh2 в Electron; первый шаг с системными пакетами | версии клиента и сервера всегда совпадают — меньше «старый supervisor» в UI; системные пакеты (Chromium, Xvfb, git) — один раз через sudo |
| B. Docker-образ | `docker run` с томами `~/.perimeter`, `~/.claude`, проекты | ~1 день: Dockerfile (Node, Chromium, Xvfb, шрифты) | одинаково везде; но проекты, git-ключи и терминал — внутри контейнера, доступ к остальному серверу неудобен; нужен Docker |
| C. Скрипт одной командой + самообновление | `curl …/install.sh \| bash`, потом `perimeter-supervisor update` | ~1,5 дня | версии клиента и сервера расходятся, обновлять руками или кнопкой |

## 2. Claude Code внутри поставки

Agent SDK тянет платформенный бинарь Claude Code (на Windows — 329 МБ), версия жёстко связана с SDK.

| Вариант | Цена сейчас | Цена потом |
|---|---|---|
| **На сервере — как сейчас (ставится вместе с supervisor'ом), в приложении — докачивается при первом запуске локального supervisor'а** (рекомендую) | ~0,5 дня (загрузка платформенного пакета в папку данных приложения) | установщик маленький; версия Claude Code совпадает с SDK |
| Всё внутри установщика | 0 | установщик ~450 МБ |
| Брать установленный у пользователя `claude` | 0 | версия «плавает» относительно SDK — ломающиеся флаги, как с 1211/подписями |

## Порядок, если брать рекомендованное

1. Сборка supervisor'а одним файлом + проверка на Velohost (вместо `npx tsx`).
2. Установщик supervisor'а по ssh из приложения (версия, папка версии, служба, откат) — заменяет ручную выкатку.
3. electron-builder + обновления.
4. Докачка Claude Code для локального supervisor'а.

Всего ~4–5 дней. До решения ничего не делаю — это развилка владельца (`docs/decisions.md`, «Открытые развилки»).
