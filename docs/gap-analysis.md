Цель — список кандидатов, из которого владелец выбирает, что брать. Наша опись — `docs/smoke.md` (2026-11-11).
Отметки: **нет** — у нас нет; **частично** — есть, но заметно беднее; цена — грубо: S (день), M (2–4 дня), L (неделя+).

Happy, Conductor, Cursor, Codex, Zed, VS Code Remote — разделы ниже (сбор 2026-11-11).

### Особое для нас
- **Канал до VPS.** Happy держит связь поверх WireGuard без открытых портов — у нас TCP до VPS режется (docs/decisions.md,
  2026-11-11). Альтернативный транспорт (UDP/QUIC/WireGuard) — кандидат, если хостинг не починит.
- **Чего нет ни у кого.** Браузер на сервере и порты с автопробросом на нескольких VPS одновременно, аккаунты и ключи на подключение,
  синк проектов между машинами — это наше, развивать дальше (UI синка пока сырой и не тестировался — долг владельца «позже»).
- **Сквозные сабагенты по аккаунтам** (просьба владельца 2026-11-15; схема ChatGPT — отправная точка, не эталон): сессия на одном
  аккаунте делегирует подзадачи воркерам на других аккаунтах/моделях (дорогой решает — дешёвый делает механику). Ложится в нашу
  архитектуру: supervisor даёт главной сессии встроенный MCP-инструмент делегирования (аккаунт + модель + промпт), сам стартует
  дочернюю **настоящую сессию** в реестре (обычный CLI-процесс с env того аккаунта, лента и разрешения в окне, родительская ссылка,
  переживает обрывы), стримит прогресс и возвращает результат. Отличие от «просто MCP-вызова» — живая сессия вместо чёрного ящика.
  Естественно стыкуется с worktree-на-сессию (двое в одной папке = конфликт правок; первая версия — общий cwd «только читать»,
  полная — worktree на воркера) и позже с пулом аккаунтов по кругу (цель делегирования — не аккаунт, а класс «дешёвый»).
  Ограничения: глубина делегирования 1 уровень, включение per-аккаунт в настройках. Цена: M.
