## Среды VPS / этот компьютер и синк проектов

Проверено на двух демо-серверах (:8795 «VPS», :8796 «этот компьютер», `DEMO_FLAVOR=local`) и запуском `electron.exe` как Node.

| Что было | Как сейчас |
|---|---|
| Локальный supervisor не запускался никогда: `spawn(process.execPath)` в Electron — это electron.exe, без `ELECTRON_RUN_AS_NODE=1` порт не открывался | флаг добавлен; проверено: supervisor поднимается и печатает адрес |
| При выходе из приложения локальный supervisor оставался жить; на Windows `kill()` бросал процессы claude | остановка при выходе, на Windows — `taskkill /T` по дереву |
| Любая строка stderr показывалась как «ошибка» | статус: запускается… / запущен / упал (код, последняя строка stderr) — в плашке связи с кнопкой «запустить» |
| Закрыл приложение в локальной среде — при следующем старте вечный реконнект | при старте в локальной среде supervisor поднимается сам |
| Синк создавал проекты другой среды с ТЕМ ЖЕ путём (`/opt/pipeline` на Windows) через 2 с после переключения, и только если переключались в этом запуске | проект связан по имени, у каждой среды свой путь; проекты другой среды — предложения «привязать папку» (догадка рядом с известными проектами, на компьютере — выбор папки и проверка, что она есть; «не предлагать»); снимки проектов сред сохраняются между запусками |

Ограничение модели «переключатель»: пока ты в одной среде, ждущие сессии другой не видны (нет даже уведомлений). Варианты решения нарисованы в Фигме («Среды и синк: два подхода»).

## Открыто (не чинили)

- Пул: если настройки папки проекта задают env/model, тёплый процесс отказывает в claim → первое сообщение падает. Нужен откат на холодный запуск с повторной отправкой ввода — делать с живым прогоном.
- AskUserQuestion уходит в `waiting_permission`, по §4 — `waiting_input` (клиент обрабатывает оба одинаково).
- Сессия в `initializing` живёт без ограничения (idle-reaper её не трогает).
- Windows: `localSup.kill()` в Electron оставляет процессы claude сиротами; `stop()` supervisor'а не гасит движки.
- После kill -9 seq может повторяться при нескольких клиентах; пути >200 символов — не проверено совпадение слага транскрипта.
- Effort: сервер отвечает NOT_IMPLEMENTED; трей не сделан.
- `toolName` в `event:message.user` не заполняется; ринг-буфер сдвигает массив целиком (O(n)).
