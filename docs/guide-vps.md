# Как подключить свой сервер (VPS)

Сессии Claude Code будут жить на сервере: закрыли ноутбук — агенты продолжают работать, открыли — видно, кто
закончил, а кто ждёт ответа. Сервер нужен любой с Linux; ставить на него руками ничего не нужно.

## Что понадобится

- **VPS с Linux** (Debian 12/13, Ubuntu 22.04/24.04) — от 2 ГБ памяти, лучше 4+.
- **Адрес и пароль root** — их присылает хостер после покупки. Вместо root подойдёт обычный пользователь с sudo.
- **Perimeter** на вашем компьютере (v0.2.1 и новее).

Открывать порты на сервере не нужно: приложение ходит по ssh (порт 22), а сам Perimeter на сервере слушает только
внутренний адрес и снаружи не виден.

## 1. Подключиться

1. Откройте **Настройки** (шестерёнка внизу или `Ctrl + ,`) → **Добавить подключение**.
2. Заполните:
   - **Название** — как угодно, например «Мой VPS»;
   - **Хост** — IP сервера, **Порт ssh** — пусто (22), **Пользователь** — `root`;
   - способ входа — **Пароль**, и пароль от хостера.
3. Нажмите **Подключить**.

Приложение один раз войдёт паролем, положит на сервер свой ключ и дальше будет входить только им.
**Пароль нигде не сохраняется** — ни на вашем компьютере, ни на сервере.

> Уже есть свой ssh-ключ на сервере? Выберите **«Мой ssh-ключ уже на сервере»** и укажите файл ключа
> (пусто — возьмутся `~/.ssh/id_*` и ssh-agent).

## 2. Поставить Perimeter на сервер

На странице подключения, во вкладке **Подключение**, — блок **«Supervisor на сервере»**:

1. **Пользователь службы** — имя, под которым будут работать агенты, например `perimeter` или ваше имя
   латиницей. Такого пользователя может не быть — его создадут. Под root агенты не работают.
2. **Установить** — приложение само поставит Node, Claude Code и службу; ход установки виден строками.
   Не поднялось — само откатится и напишет почему.
3. **Возможности сервера** — отметьте, что нужно, и **Поставить выбранное**:
   - **Git** — проекты из git, статус и дифы в «Файлах»;
   - **Терминал** — настоящий терминал (цвета, vim, htop); перезапустит supervisor;
   - **Браузер на сервере** — превью и сайты прямо на сервере, вход в аккаунты через браузер;
   - **Docker для агентов** — базы и сервисы в контейнерах, без прав root у агентов.
   Нужен вход под root (или sudo). Что нельзя поставить кнопкой, помечено «вручную» с причиной.

Через минуту-две в боковой панели появится секция сервера с зелёной точкой.

## 3. Аккаунт и первая сессия

1. Вкладка **Аккаунты и модели** → **+ Добавить аккаунт**:
   - **Подписка Claude** — вход откроется в браузере на сервере (или войдите кодом / токеном `claude setup-token`);
   - **Ключ API** — ключ Anthropic или шлюза (z.ai и др.) по шаблону.
2. **Новый проект** (кнопка с папкой у секции сервера) → пустой, из git или готовая папка.
3. **+** у проекта → пишите задачу.

## Если что-то не так

| Что видно | Что делать |
|---|---|
| «пароль не подошёл» | Проверьте пароль; у некоторых хостеров вход root по паролю выключен — тогда «Мой ssh-ключ уже на сервере» или пользователь с sudo |
| «нет ответа за 20 с» | Неверный адрес/порт или сервер ещё загружается после покупки; порт 22 должен быть открыт в панели хостера |
| Установка откатилась | Текст причины — под кнопкой; лог службы на сервере: `journalctl -u perimeter -n 100` |
| Возможность помечена «вручную» | Причина — под ней; например, в Ubuntu chromium только snap — браузер по `docs/deploy.md` |
| «поставить может только root» | Вход не под root и без sudo — выполните показанную команду под root или подключитесь под root |
| Агенту нужно пушить в GitHub | Ключ сервера для GitHub — пока вручную: `docs/deploy.md`, «Git на сервере» |

## Что где лежит

- На вашем компьютере: подключения и ключ приложения — `~/.perimeter-client/` (ключ: `keys/perimeter-<пользователь>_at_<адрес>`).
- На сервере у пользователя службы: `~/.perimeter/` — аккаунты, сессии, проекты; `~/.perimeter/server/` — версии
  Perimeter (текущая и прошлая для отката). Служба — `perimeter` (`systemctl status perimeter`).
- Обновление — кнопкой **Обновить** в том же блоке, когда вышла новая версия приложения; откат — **Откатить**.

## Безопасность

- Пароль используется один раз и не хранится.
- Наружу на сервере ничего не открыто: приложение подключается через ssh-туннель.
- После того как подключение заработало, вход по паролю на сервере можно выключить (под root):
  `echo 'PasswordAuthentication no' > /etc/ssh/sshd_config.d/00-no-password.conf && systemctl reload ssh`
  (отдельный файл с `00-` — у облачных образов бывает `50-cloud-init.conf` с паролем «да», а у sshd побеждает
  первое значение). Только если у вас самих есть ключ для входа — иначе входить сможет одно приложение.
